# Side-by-Side AI Code Comparison Arena (`code-arena-mvp`)

An interactive, high-fidelity playground to generate, compare, and judge code solutions generated by different Large Language Models (LLMs) side-by-side. 

This tool helps developers, prompts engineers, and AI researchers test the code generation capabilities of various models under the exact same prompts and constraints, and utilizes an AI Judge to determine the winning solution with an in-depth scorecard.

---

## Key Features

- 👥 **Side-by-Side Comparison**: View and compare code outputs from two different models simultaneously with live markdown rendering and syntax highlighting.
- 🤖 **Multi-Provider LLM Support**:
  - **OpenAI**: GPT-4o, GPT-4, etc.
  - **Anthropic**: Claude 3.7 Sonnet, Claude 3.5 Sonnet, Claude 3 Opus, etc.
  - **Gemini**: Gemini 1.5 Pro, Gemini 1.5 Flash, etc.
- ⚖️ **AI Judge Scorecard**: Run an evaluation using a third model as an unbiased judge. It rates both outputs on *Correctness*, *Code Quality*, and *Explanations*, renders a detailed verdict, and outputs a structured winner classification (Model A, Model B, or Tie).
- 💾 **File-Based Persistence**: 
  - Challenges are organized under `/challenges` with a `prompt.md` and optional base code.
  - LLM outputs, clean code blocks, meta parameters, and judge verdicts are saved to disk under `/outputs` (gitignored, saved locally only) for offline review and caching.
- ⚙️ **Configurable Generation Options**: Toggle caching (`forceRegenerate`) and auto-judging directly from the control panel.
- 🔑 **Local API Key Storage**: Keys are saved safely in your browser's local storage and passed securely via request headers.

## Project Structure

```text
├── challenges/                 # Saved challenge definitions (prompts and base code)
│   └── [challenge-slug]/
│       ├── prompt.md           # The task prompt
│       └── code.js             # Optional pre-existing base code

│       ├── [model-a-slug].js   # Extracted executable code block from Model A

```

## Installation & Setup

### 1. Clone & Install Dependencies
First, ensure you have [Node.js](https://nodejs.org/) installed, then run:
```bash
npm install
```

### 2. Configure API Keys
1. Start the server (see below).
2. Open the application in your browser.
3. Click the **Settings** icon (gear) in the top-right corner.
4. Input your API keys for **OpenAI**, **Anthropic**, and/or **Gemini**.
5. Click **Save API Keys**. Keys are stored safely in `localStorage` in your browser.

---

## Running the Application

### Development Mode (with hot-reloading)
Runs the server with automatic watch mode enabled:
```bash
npm run dev
```

### Production/Standard Mode
Runs the server directly:
```bash
npm run start
```

Once running, navigate to **[http://localhost:3000](http://localhost:3000)** in your web browser.

## API Documentation

The Node.js Express backend exposes the following endpoints:

### 1. `GET /api/challenges`
Returns a list of all challenges saved in the `/challenges` directory, along with details of whether they have stored outputs.

### 2. `GET /api/outputs/:id`
Retrieves saved comparison outputs for a challenge. Supports optional query parameters `modelA` and `modelB` to load model-specific outputs.

### 3. `POST /api/compare`
Sends the prompt and context to both chosen LLMs in parallel.
- **Parameters**: `prompt`, `existingCode`, `existingCodeFile`, `challengeId`, `modelA`, `modelB`, `modelAName`, `modelBName`, `forceRegenerate`.
- **Headers**: Requires `x-openai-key`, `x-anthropic-key`, and/or `x-gemini-key` header parameters.

### 4. `POST /api/judge`
Calls a third model to act as an evaluator between the two outputs. Saves the resulting evaluation as `judge.md` in the challenge output folder.
